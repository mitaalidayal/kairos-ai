How Kairos decides

Six narrow agents run in a fixed order for every scheduled message. Only the detector reads free text, and it can only return a label. Any error becomes WAIT + BLOCK.

1Signal AgentDates every prayer request and pastoral note, normalizes attendance, giving, volunteering and contact signals. Text a member did not consent to share with AI is dropped here, before any other agent sees it.
2Sacred Moment DetectorLabels each text: sacred · ambiguous · praise · other person · resolved · absence · routine, plus a sacred type and an injection flag. Output is validated against the enum; anything else becomes "ambiguous". Text is data, never instructions.
3Decision AgentPriority rules, first match wins: sacred window → consent restricted → ambiguous → silent drop-off → someone else's crisis → milestone → guardrail holds → healthy ask.
4Routing AgentPicks the person with the strongest relationship and says why (role, strength, last contact, runner-up).
5Draft AgentWrites a thank-you (no ask) or a private brief for the routed person. Never sends anything.
6Guardrail AgentIndependent final check from the raw data: consent, keyword second opinion, minors, opt-outs, 30-day cap, channel consent. It can only downgrade (never to ASK), and it brings in a human when something sacred might otherwise be held silently.
✓A personEvery CARE, THANK and uncertain WAIT lands here. People log contacts (which schedule a 14-day follow-up), approve or edit thank-yous (re-checked for asks), and keep, escalate or release holds (hard constraints like minors and opt-outs can never be released).
